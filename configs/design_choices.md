# Per-stage design choices (A2 deliverable). Fill every cell.
| Stage | Problem statement | Data | Model | Methods | Design | Development | Deployment | MLOps |
|---|---|---|---|---|---|---|---|---|
| 0 Frame | Read scanned Bangla math textbook pages and answer questions grounded in them, citing the source page. Success metric: ECE <= 0.05 (calibration, primary NFR) on top of the course-wide baseline (groundedness >= 0.90, citation accuracy >= 0.90). | 704 page-image scans (PNG) from two NCTB textbooks — `higher_math` (342 pages) and `math` (362 pages), public domain. Split by document (never mix `higher_math`/`math` pages across train/eval) to avoid leakage. | n/a at this stage | n/a at this stage | `src/doc_agent/ingest/loader.py` reads `data/raw/**` into `Page` objects, one per image; `doc_id` is derived per-book from the filename prefix. | `tests/` cover contracts + structure; corpus fetch is scripted (`scripts/get_data.sh`, validated against an expected image count). | Runs locally, CPU-only (no GPU available on the dev machine; `device` in config falls back to CPU everywhere it's requested). | Corpus is not committed to git (291 MB); `scripts/get_data.sh` re-fetches it from a versioned archive. |
| 1 Ingest+Enhance | Turn raw scans into clean, upright, binarized page images the downstream layout/OCR stages can rely on. | Input: raw page PNGs. Output: preprocessed PNGs at `data/interim/preprocessed/<doc_id>/`. No labels used at this stage. | Classical CV only (OpenCV) — no learned enhancement model. Enhancement (VAE/diffusion denoiser) is the bonus-tier stage and is currently disabled (`enhance.run()` is commented out in `pipeline.py`). | Skew estimate via `minAreaRect` on the Otsu-thresholded foreground, corrected with an affine warp; `fastNlMeansDenoising` for noise; adaptive Gaussian thresholding for binarization. Key params: `denoise_strength=10`, `adaptive_block_size=31`, `adaptive_c=15`. | `ingest/preprocess.run(pages, cfg)` returns updated `Page` objects pointing at the new image path; pure function, no side effects on `Page.id`. | Deterministic classical pipeline — no training, so no experiment logging needed; behavior is config-driven and testable page-by-page. | Runs page-by-page on CPU; `preprocess.max_pages` config knob caps how many pages are processed per run (used to keep dev iterations fast). | No enhancement model to monitor. `preprocess.max_pages` is the main operational lever for run duration/cost. |
| 2 Layout | Segment each page into reading-ordered, OCR-ready text lines, mathematical formula blocks, headings, and geometric diagrams — full-page or coarse paragraph bounding boxes fail on line-level OCR and multimodal textbook grounding. | Input: raw or preprocessed page images (PNG). Output: `Region` objects (`page_id`, `bbox`, `kind` ∈ {heading, text, math, figure}). No manual labels used; unsupervised morphological & projection layout discovery. Emits per-page structured metadata to `data/interim/layout/regions.jsonl` and 4-color visual overlays to `data/interim/layout/overlays/`. | Classical projection-profile and connected-component morphological line segmentation (`classical:projection-lines`) with mathematical headline/fill-ratio profiling — no learned detector network required. ViT/GNN layout modeling not needed as classical projection achieves exact line-level encapsulation. | Multi-pass hybrid layout pipeline: (1) Margin noise suppression (5% borders); (2) Callout theorem border suppression to retain internal text unbroken; (3) Contour & connected-component diagram/figure isolation with nearby label absorption (<= 45px); (4) Horizontal projection line extraction with peak-and-valley projection splitting on dense multi-paragraph blocks (> 180px); (5) Tall line / fraction preservation (`max_single_line_height = 200`); (6) Vertical stray bbox absorption (<= 22px) & speckle pruning (< 600px^2); (7) Prominent top-of-page heading classification (`heading_factor = 1.45`, y < 0.12 H); (8) Math line classification based on headline/maatra absence (< 0.28), sparse fill ratio (< 0.10), and fraction structures; (9) Column-aware reading-order sorting. | `src/doc_agent/vision/layout.detect(pages, cfg) -> list[Region]`. Computes quantitative page area metrics (`fig_area_px`, `math_area_px`, `text_area_px`, `fig_area_frac`, `math_area_frac`, `text_area_frac`, `total_ink_bbox_frac`), exports JSONL metadata and color-coded BGR bounding-box overlay images (`heading`: blue, `text`: green, `figure`: red, `math`: purple). | Iteratively evaluated on real NCTB benchmark scans across diverse archetypes (algebra, geometry proofs, coordinate graphs). Verified with comprehensive unit test suite (`tests/test_layout.py`, `tests/test_layout_artifacts.py`, `tests/test_stray_absorption.py`, `tests/test_math_layout_comparison.py`). | Fast CPU-only execution (~0.08–0.12s per page; ~70s for all 704 pages). Runs directly on raw or preprocessed scans without GPU/neural network dependencies. | Rule-based, deterministic, zero training drift. Parameterized via `configs/config.yaml`. Overlays and `regions.jsonl` versioned alongside EDA metrics and 90/5/5 splits (`data/splits/`) for pipeline regression checks. |
| 3 OCR | Transcribe each detected line region to text. | Input: line-cropped images. Output: `Chunk` objects, one per page (lines joined in reading order) — matches the `Chunk` contract (`id, doc_id, text, page_ids, score`). | Primary/reproduced baseline: **Tesseract** (`ocr.backend: tesseract`, `languages: "ben+eng"`, `psm: 7` — single text line), using `tessdata_best` trained data. Also implemented and compared: TrOCR-style VisionEncoderDecoder models — both `microsoft/trocr-base-printed` (English-only, fails badly on Bangla — hallucinates English business text) and a Bengali-finetuned `nightsagittariuswolf/SWIN_TrOCR_Bangla_model` (produces real Bangla script but still weak on short/noisy crops). Tesseract-on-lines gave the best output of the three and is the configured default. | Line images are padded (`crop_padding`) before recognition so glyphs at segmentation boundaries aren't clipped; `--oem 1` (LSTM engine). TrOCR path (kept in `Reader` for comparison) needed generation-config patching to load the Bangla checkpoint (some `null` fields reject under current `transformers`). | `vision/ocr.Reader` picks the backend from `cfg['ocr']['backend']`; `transcribe(regions, cfg) -> list[Chunk]` groups line text back into one `Chunk` per page. | Compared 3 OCR configurations manually on the same real pages/regions before choosing Tesseract; documented in commit history (`b3b789d using tesserect gives better output`, `c9634c6 tried a bengali finetuned TrOCR model`). | Tesseract subprocess call per line crop, CPU; no GPU dependency (unlike the TrOCR path, which needs `torch`). | OCR backend is a one-line config swap (`ocr.backend`); no quality regression monitoring yet — flagged as an A3/A4 gap. |
| 4 Index | Turn page-level OCR text into retrieval-sized chunks, embed them, and build a searchable vector index. | Input: per-page `Chunk` objects from OCR. Output: re-chunked `Chunk`s + a FAISS index + `chunks.jsonl` + `metadata.json` sidecar. | Chunking: custom semantic splitter (no external model) using Bangla textbook boundary markers (অধ্যায়, উদাহরণ, সমাধান, উপপাদ্য, প্রমাণ, সূত্র, সংজ্ঞা, অনুশীলনী, কাজ) to avoid cutting a worked example or proof mid-way, then token-windowed (`chunk_tokens=256`, `overlap=32`) only when a unit exceeds the window. Embedding: currently `shihab17/bangla-sentence-transformer` (Bangla-finetuned SBERT, expected 768-dim) for comparison against the previous `sentence-transformers/all-MiniLM-L6-v2` 384-dim baseline, which is kept commented in `configs/config.yaml` for rollback. Vector index: FAISS `IndexFlatIP` on L2-normalized vectors (cosine via inner product). | `index.chunking: "semantic"` (default) vs `"fixed"` (plain token windows) — semantic mode is the reproduced choice for A2. Embeddings are L2-normalized so inner product = cosine similarity. | `index/chunk.split(chunks, cfg)` -> `index/embed.encode(chunks, cfg)` -> `index/store.build(chunks, vectors, cfg)`; `embed.py` has a deterministic hash-embedding fallback if the sentence-transformers model can't load (keeps CI/offline runs green). | `index/store.load()` sanity-checks `index.ntotal == len(chunks)` on read; build metadata (`chunk_count`, `embedding_dim`, `embedding_model`, `index_type`, timestamp) is written alongside the index for reproducibility, so test runs show which embedder produced the FAISS file. | `faiss:flat-ip` chosen specifically because `faiss:hnsw` (`IndexHNSWFlat`) segfaults reliably on this team's Windows + faiss-cpu 1.8 + Python 3.12 setup — documented as a comment directly in `configs/config.yaml`. Runs CPU-only, single process; the Bangla SBERT model is larger than MiniLM, so expect slower CPU embedding. | Index is rebuilt from scratch each run (`scripts/build_index.sh`); no incremental updates yet. Corpus coverage indexed vs. total corpus is tracked in Section 5 of the A2 form. |
